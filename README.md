# \# donkeycar-practice

# 

# Donkey Car シミュレータ(gym-donkeycar)を使い、Python で自動運転の基礎を学んだ実験記録である。機械工学科の学部生が、「AI が出したコードを読んで正しいか判断でき、直せるようになる」ことを目標に、cte 制御・画像処理・CNN 学習という 3 つの異なるアプローチを実装し比較した。

# 

# \## 環境

# 

# \- Windows, Anaconda(conda 環境名: `donkey`, Python 3.9.25)

# \- numpy 1.23.5, gym 0.25.2, tensorflow 2.9.0, donkeycar 5.0.0

# \- gym-donkeycar は互換性の関係で v21.02.20 のタグ版を使用

# \- シミュレータ: donkey\_sim.exe(v25.10.06)

# 

# \## 1. cte による P/D 制御(`drive\_p.py`, `drive\_recover.py`)

# 

# シミュレータが返す `cte`(コース中心からの距離)を使い、`steer = -kp\*cte - kd\*d\_cte` という式でハンドルを決める制御である。

# 

# P 制御のみ(kp=0.5)ではカーブで外側に膨らみ脱輪した。D 項(kd=1.0)を加えると振動が抑えられ、500 ステップの完走を達成した。ただし kp を上げて反応を強めると、逆に振動が大きくなって脱輪することもあり、パラメータの選び方に明確なトレードオフがあった。

# 

# 「壁にぶつかったらバックする」自動復帰ロジックも実装した。cte の絶対値やハンドルの張り付きを検知条件にして試したが、バック終了直後に車体の向きが直っていないまま前進を再開し、反対方向へ大きく振れて脱輪するケースが多く、実用化には至らなかった。これは cte とその変化量だけでは車体のヨー角(向き)を表現できないという、この手法の構造的な限界だと考えている。

# 

# \## 2. 色情報による車線追跡(`drive\_line.py`, `hsv\_probe.py` ほか)

# 

# `cte` を使わず、カメラ画像だけから自己位置を推定する試みである。実際のレーン検出手法(HSV 色空間によるマスク、鳥瞰図変換、ヒストグラムによるピーク検出、スライディングウィンドウ)を段階的に実装した。

# 

# 黄色い線を HSV でマスクし重心位置を cte の代わりに使う方式から始め、遠近歪みを取り除くための `cv2.warpPerspective` による鳥瞰図変換、下から上へ追跡するスライディングウィンドウへと発展させた。最終的にぶつかった壁は、道路の片側に影が落ちると同じ白線でも HSV 値(特に色相)が別物として検出されてしまい、単一のしきい値では影の有無を両立して扱えないという点である。単眼カメラの色情報だけに頼る手法の一般的な限界に、実験を通じて自分で行き当たった形になった。

# 

# \## 3. CNN による挙動模倣(Behavioral Cloning)

# 

# `donkey` コマンドで走行データ(カメラ画像+操作記録)を収集し、Keras の CNN に学習させた。

# 

# | モデル | データ件数 | 結果 |

# |---|---|---|

# | mypilot | 7,019 | Full Auto で 1 周半 |

# | mypilot2 | 10,770(影のカーブを重点録画) | 3 周強で影のカーブに脱輪 |

# | mypilot3 | 20,080(コース全体を丁寧に周回) | 明確な脱輪なく継続周回 |

# 

# データ量を増やすほど学習曲線(loss)の初期値・収束値ともに改善し、特に多様な状況を含む均質なデータが有効だった。学習済みモデルの走行中に cte を記録したところ、単純な蛇行だけでなく、コース上の障害物(コーン)を避ける挙動も自発的に学習していることを確認した。一方で、あるカーブでは cte が ±3 を超える揺れを繰り返しており、お手本にした自分の運転の癖がそのままモデルに反映されている可能性が高いと見ている。

# 

# \## 学びの要約

# 

# cte のような特権的な数値が使えない実車環境では、色による画像処理は照明変化(影)に弱く、単純なルールベースの手法には明確な限界がある。挙動模倣は「お手本の質」がそのまま性能の上限になるが、データ量と多様性を増やすことで着実に性能が向上した。単純な制御則で対処しきれない状況(急な蛇行からの復帰など)には、CNN が画像から学習した暗黙的な判断のほうが柔軟に対応できる場合があることも分かった。

# 

# \## 主なファイル

# 

# \- `drive\_straight.py`: gym-donkeycar の基本的な使い方の確認

# \- `drive\_p.py`: cte を使った P/D 制御

# \- `drive\_recover.py`: 衝突検知とバック復帰ロジック

# \- `drive\_line.py`: HSV + 鳥瞰図変換 + スライディングウィンドウによる車線追跡

# \- `look\_obs.py`, `hsv\_probe.py`, `hist\_probe.py` ほか: 画像・データの中身を確認する調査用スクリプト

# \- `manage.py`, `myconfig.py`, `config.py`: donkeycar フレームワークの標準ファイル(録画・学習・自動運転の実行に使用)
